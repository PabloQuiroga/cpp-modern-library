# ADR 004: Uso de Identificadores Únicos para la Anulación de Suscripciones

## Estado
Aceptado

## Contexto
El diseño original del `EventBus` proponía que la función `unsubscribe` recibiera el mismo `Callback` (función) que se utilizó en la suscripción para poder localizarlo y eliminarlo del sistema.

## Decisión
Hemos decidido cambiar la firma de la API para que la función `subscribe` devuelva un `SubscriptionId` (un identificador numérico único) y que la función `unsubscribe` utilice este ID en lugar del callback para procesar la eliminación.

## Justificación
- **Limitación del Lenguaje**: En C++, el tipo `std::function` no proporciona un operador de comparación (`==`). Esto hace que sea técnicamente imposible comparar dos callbacks para determinar si son la misma función, especialmente cuando se utilizan lambdas o funciones anónimas.
- **Precisión**: El uso de un ID único garantiza que se elimine la suscripción exacta solicitada, evitando ambigüedades.
- **Eficiencia**: La búsqueda de un ID numérico es más directa y menos propensa a errores que intentar comparar firmas de funciones complejas.

## Consecuencias
- **Cambio en la API**: Los componentes que se suscriban a un evento deben ahora almacenar el `SubscriptionId` retornado para poder desuscribirse posteriormente.
- **Simplicidad en la Implementación**: La lógica de eliminación se simplifica a una búsqueda de un valor entero dentro de la estructura de datos.
